## What This Module Does

Optional encrypted backup of the entire `app-data.db` SQLite file to Cloudflare R2:
- User provides Cloudflare account ID, bucket name, R2 API token (access key ID + secret)
- Secret is stored in OS keychain (never SQLite, never the backup itself)
- **Backup**: reads the raw `.db` file, encrypts with [age](https://github.com/str4d/rage) (passphrase-based, scrypt KDF), uploads as `intelquery/backup.age` to the bucket
- **Restore**: downloads the blob, decrypts (wrong passphrase fails early — age uses AEAD), validates it's a real SQLite file, atomically swaps the live DB
- No scheduling — always user-triggered

## Key Files — What to Know Before Editing

### `sync.rs`

**Configuration**
- Settings stored in `settings` table (via `appdb::set_setting`): `r2_account_id`, `r2_bucket`, `r2_access_key_id`, `r2_endpoint`, `last_backup_at`
- Secret stored in keychain: `r2_secret_access_key` (constant `R2_SECRET_ACCOUNT`)
- `get_config()` returns `None` if any required setting is absent; checks keychain for `connected` flag
- `clear_config()` removes all settings and best-effort deletes the keychain entry

**Backup flow (`backup(state, passphrase)`)**
1. Read `state.app_db_path` directly (rollback-journal guarantees single-file consistency)
2. `encrypt(plaintext, passphrase)` → age ciphertext
3. PUT to `intelquery/backup.age` via S3-compatible API
4. Record `last_backup_at` in settings

**Restore flow (`restore(state, passphrase)`)**
1. GET `intelquery/backup.age` from R2
2. `decrypt(ciphertext, passphrase)` — age AEAD rejects wrong passphrase immediately
3. Close the pool (`guard.close()`) — required on Windows to overwrite an open SQLite file
4. Copy current DB to `.bak` as safety net
5. Write new bytes, reopen pool via `appdb::init_pool()`
6. Remove stale WAL sidecar files (`-wal`, `-shm`) if present

**`build_bucket()`** — constructs an S3-compatible `Bucket` client using the `rust-s3` crate with `path_style` enabled (required for R2)

**Encryption** — `age::Encryptor::with_user_passphrase` / `age::Decryptor`. The passphrase must be non-empty (checked before calling encrypt/decrypt).

### `SyncSettings.tsx`
- UI sections: R2 connection form, backup/restore controls, last-backup timestamp
- Shows `connected: true` status from `get_config()` when the secret is present in keychain
- Passphrase input is always local state — never persisted, never sent to Rust until backup/restore

### Tauri Commands (in `lib.rs`)

| Command | Purpose |
|---------|---------|
| `sync_get_config` | `Option<R2Config>` |

## Critical Constraints

- **Single-file backup assumption**: backup reads the raw `.db` file. Works because `appdb.rs` uses `SqliteJournalMode::Delete` (not WAL). Do not change the journal mode.
- **Passphrase required**: never proceed without a non-empty passphrase — the encrypted blob is public if the bucket is misconfigured.
- **Never include secrets in the backup**: the `.db` file has no passwords or API keys by design. Verify before any schema change to `appdb.rs`.
- **Windows file lock**: the pool must be closed before overwriting the `.db` file. The `guard.close()` in the restore flow is essential.
- **Backup is not incremental**: each backup replaces the single object. There is no version history.

## What Is NOT Backed Up

- Connection passwords (`conn_*_password`) — in OS keychain
- OpenRouter API key (`openrouter_api_key`) — in OS keychain
- R2 secret (`r2_secret_access_key`) — in OS keychain
- Any browser localStorage data
