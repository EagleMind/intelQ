## What This Module Does

**An AI answer is a draft that becomes a saved asset, not the final product.** Each question answered once
should mean fewer AI calls later.

- **Save question** stores `{question, sql, source}` at any time — no run required. `sql` may be empty: a question can be
  saved before it has SQL, and its SQL is filled in later (**Update saved** after the AI drafts it).
- When the user presses **Ask**, saved questions are matched first (`findMatches`, no AI). A strong match shows
  `SavedMatchCard`; **Run saved** re-runs the exact stored SQL (same SQL → same numbers) and stores the typed
  phrasing as an alias, so rephrasings stop costing AI calls. **Ask AI anyway** keeps the full-AI flow.
- Saved questions work with **no AI configured** — offline, provider removed, or AI blocked.
- The reuse metric (`question_stats`): saved runs vs new AI drafts over the last 30 days. Saved runs going up while
  AI drafts go down is the goal.

Deliberately **not** here (user decision 2026-11-08): no Verified badge, no author / "saved by", no sharing.

## SQLite Schema (app-data DB, created via `appdb::init_schema`)

```sql
CREATE TABLE IF NOT EXISTS saved_questions (
  id            TEXT PRIMARY KEY,               -- uuid v4
  connection_id TEXT NOT NULL,
  question      TEXT NOT NULL,                  -- display name / original phrasing
  aliases       TEXT NOT NULL DEFAULT '[]',     -- JSON array of other phrasings (max 20, case-insensitive dedupe)
  sql           TEXT NOT NULL,                  -- '' = question saved without SQL yet
  source        TEXT NOT NULL DEFAULT 'ai',     -- 'ai' | 'edited' | 'manual'
  run_count     INTEGER NOT NULL DEFAULT 0,
  last_run_at   TEXT,
  created_at    TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at    TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE TABLE IF NOT EXISTS question_events (
  id                INTEGER PRIMARY KEY AUTOINCREMENT,
  connection_id     TEXT NOT NULL,
  kind              TEXT NOT NULL,              -- 'ai_draft' | 'saved_run'
  saved_question_id TEXT,
  at                TEXT NOT NULL DEFAULT (datetime('now'))
);
```

Both tables live in the single app-data file, so the R2 whole-file backup (MOD-005) carries them with no sync changes.
Restoring an older backup recreates them empty.

## Matcher (`questionMatch.ts`)

- Tokens: lowercase, `@table` tags kept whole, punctuation + filler words dropped, light stemming (`s`/`ies`/`ed`/`ing`).
- Score: Jaccard over token sets, best of question name + aliases.
- **Qualifiers must agree**: numbers and words like `last/this/next/today/not/without` — if they differ, the score is
  multiplied by 0.6 so "orders this week" never strongly matches "orders last week" and "top 5" never matches "top 10".
- Thresholds: `STRONG_MATCH = 0.6` (match card), `NEAR_MATCH = 0.35` (suggestions in `HelpCard`).

## Invariants

- Saved SQL is never executed from this module — every run goes through `NLQInterface.executeGuarded` (safety analyzer + read-only lock). Panel and card only call back. @anchor src/components/saved/SavedQuestionsPanel.tsx
- IDs are uuid v4, never deterministic. @anchor src-tauri/src/saved_questions.rs
- Schema changes are `CREATE ... IF NOT EXISTS` only, so restored older backups keep working. @anchor src-tauri/src/saved_questions.rs
- `appdb_delete_connection` must call `saved_questions::delete_for_connection` (questions + events). @anchor src-tauri/src/lib.rs
- A match never runs on its own — the user picks **Run saved** or **Ask AI anyway**. @anchor src/components/saved/SavedMatchCard.tsx
- `SavedQuestionsProvider` sits inside `DbProvider` (reads `status.connectionId`). @anchor src/App.tsx

## Internal

- The context reloads on `status.connectionId` change (the `loadedForRef` pattern from MOD-002). @anchor src/store/SavedQuestionsContext.tsx
- `rename` keeps the old name as an alias so it stays findable. @anchor src/store/SavedQuestionsContext.tsx
