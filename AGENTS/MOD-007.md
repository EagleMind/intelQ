# MOD-007 — App Shell & Routing

## Scope (files this agent owns)

```
src/App.tsx                          ← root component, Shell, provider tree, header, modals
src/components/DataExplorer.tsx      ← left-panel: table list, schema view, annotation badges
```

Setup flow (owned by MOD-008):
```
src/components/SetupGuide.tsx        ← onboarding: connect DB, configure AI, enter workspace
```

## What This Module Does

The outermost layer of the application:
- **Provider tree** (`App`): `ThemeProvider → DbProvider → AiSettingsProvider → AnnotationProvider`
- **Shell**: header, connection status bar, main content area, footer
- **Routing** (no router library): state-based view switching — `showWorkspace ? <Workspace> : <SetupGuide>`
- **Onboarding**: `onboarding_done` setting persisted via `sync.setSetting`. User must explicitly complete the setup guide before the workspace is shown.
- **Modals**: `ConnectionsManager`, `SyncSettings`, `AnnotationPanel` — all managed from Shell state
- **DataExplorer**: left-panel table browser; integrates with MOD-002 (annotation badges + "Annotate" button)

## Key Files — What to Know Before Editing

### `App.tsx`

**Shell state**
- `onboardingDone` / `onboardingLoaded`: async-loaded from `sync.getSetting('onboarding_done')`. Prevents flash of workspace before the check completes.
- `booting`: `initializing || !aiLoaded || !onboardingLoaded` — renders a spinner until all async inits finish
- `showWorkspace = onboardingDone` — workspace is shown only after the user has explicitly finished onboarding

**Provider order** (outermost → innermost):
```
ThemeProvider
  DbProvider                 ← must be before AiSettings and Annotations
    AiSettingsProvider
      AnnotationProvider     ← must be inside DbProvider (reads connectionId)
        Shell
```

**Header buttons** (only shown after `showWorkspace`):
- Disconnect (when connected)
- Manage Connections → `setShowConnectionsManager(true)`
- Annotate (when connected) → `openPanel()` from `useAnnotations()`
- Sync → `setShowSync(true)`
- ThemeToggle (always visible)

**`<AnnotationPanel />`** is rendered at the Shell level — it self-manages its own visibility via `AnnotationContext.isPanelOpen`.

### `SetupGuide.tsx`
- Multi-step onboarding: connect a DB, configure AI, done
- `onEnter` callback: called when user clicks "Enter IntelQuery" — sets `onboardingDone = true` and persists
- `onOpenConnections` callback: opens `ConnectionsManager` from within the guide

### `DataExplorer.tsx`
- Reads `tables` and `schema` from `DbContext`
- Renders a table list; each row shows `<AnnotationBadge>` (MOD-002) if the table has annotations
- "Annotate" button in the header calls `openPanel()` for the whole panel
- Hover-visible tag icon on each row calls `openPanel(tableName)` to jump directly to that table
- Schema view: raw schema text displayed in a collapsible panel

## Rendering Logic

```
booting?       → spinner
showWorkspace? → <Workspace> (DataExplorer + NLQInterface)
else           → <SetupGuide>
```

`Workspace` is intentionally a simple layout component defined at the top of `App.tsx` — it should stay lean. Feature components own their own logic.

## Adding a New Top-Level Feature

1. Create the feature component (its own module / CONTEXT.md if substantial)
2. If it needs a modal: add a `show<Feature>` state variable to `Shell`
3. If it needs a header button: add it in the header button group (only shown in `showWorkspace`)
4. If it needs a context/provider: wrap `Shell` in the new provider inside `App`, following the provider order above
5. Register in `AGENTS/INDEX.md`

## Critical Constraints

- **Provider order matters**: `AnnotationProvider` must be inside `DbProvider` — it calls `useDb()` on mount. Wrapping in the wrong order causes a context mismatch crash.
- **`onboardingDone` is async**: always wait for `onboardingLoaded` before rendering. The `booting` flag handles this.
- **`showWorkspace = onboardingDone`**: do NOT add `configuredAtStart ||` back to this condition — the intent is that completing any single step never skips the rest of the setup guide.
- **AnnotationPanel must render at Shell level**: it's a full-screen modal; rendering it inside a smaller container would clip it.

## Related Modules

- This module integrates all others — always check the relevant module's CONTEXT.md when the change touches that module's contract (e.g., adding a header button that calls a context method)

## Contract

- Provider order is fixed: `ThemeProvider → DbProvider → AiSettingsProvider → AnnotationProvider → Shell`. @anchor src/App.tsx
- `showWorkspace = onboardingDone` — render `<SetupGuide>` (MOD-008) when not done, `<Workspace>` when done. @anchor src/App.tsx

## Invariants

- `AnnotationProvider` must be inside `DbProvider` — swapping order causes a context crash at runtime. @anchor src/App.tsx
- `showWorkspace = onboardingDone` — do NOT add `|| configuredAtStart` back; intent is that no single step skips the full guide. @anchor src/App.tsx
- `AnnotationPanel` must render at Shell level — it is a full-screen modal and clips if rendered inside a smaller container. @anchor src/App.tsx
- Always wait for `onboardingLoaded` before rendering the workspace — never assume `onboarding_done` is synchronously available. @anchor src/App.tsx
- `SetupGuide` callbacks (`onOpenConnections`, `onEnter`) must point to Shell state methods — never pass undefined. @anchor src/App.tsx

## Internal

- `booting = initializing || !aiLoaded || !onboardingLoaded` — single flag for all async inits; spinner shown until all three are ready. @anchor src/App.tsx
- New top-level features: add `show<Feature>` state to `Shell`, show the header button only inside `showWorkspace`, wrap `Shell` in the new provider. @anchor src/App.tsx
- `Workspace` is a thin layout component defined at the top of `App.tsx` — keep it lean; feature logic belongs in the feature module. @anchor src/App.tsx
