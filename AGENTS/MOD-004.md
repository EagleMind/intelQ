# MOD-004 — App Data Store & Credentials

## Scope (files this agent owns)

```
src-tauri/src/appdb.rs        ← SQLite pool, schema init, CRUD for connections + settings
src/services/sync.ts          ← frontend wrappers: listConnections, saveConnection, getSetting, etc.
```

Cross-cutting (shared with MOD-001):
```
src-tauri/src/lib.rs          ← appdb_* Tauri commands, keyring helpers
```

## What This Module Does

IntelQuery's local persistence layer. All user data that is NOT a secret lives here:
- Saved connection definitions (host, port, database, username — NOT password)
- App/UI settings (AI provider, endpoints, read-only lock, onboarding state, R2 config)
- Annotations (owned by MOD-002, schema created by this module via `annotations::init_schema`)

The SQLite file (`app-data.db`) is the unit that gets backed up to Cloudflare R2 (MOD-005).
Secrets (connection passwords, API keys, R2 secret) are stored in the OS keychain — **never here**.

## Key Files — What to Know Before Editing

### `appdb.rs`
- `init_pool(path)` — opens/creates the SQLite file and runs `init_schema`. Uses **rollback-journal mode** (not WAL) so the single `.db` file is always the authoritative snapshot for R2 backup.
- `init_schema(pool)` — creates `connections` and `settings` tables, then calls `annotations::init_schema(pool)` for MOD-002's table. Adding new tables: create a migration here.
- `ConnectionRecord` — mirrors the TypeScript `ConnectionRecord` interface. `port` is `i64`.
- All functions return `Result<T>` (anyhow). Map to `String` at the Tauri command layer.
- Settings table: `key TEXT PRIMARY KEY, value TEXT` — generic key-value. Any module can store settings here.

### `lib.rs` — appdb Tauri commands

| Command | Purpose |
|---------|---------|
| `appdb_list_connections` | `Vec<ConnectionRecord>` |
| `appdb_save_connection` | Upsert a connection record |
| `appdb_delete_connection` | Delete connection + cascade delete annotations |
| `appdb_get_setting` | `Option<String>` |
| `appdb_set_setting` | Upsert key-value |
| `appdb_delete_setting` | Remove a key |
| `appdb_get_settings` | `HashMap<String, String>` all settings |

**Cascade delete** in `appdb_delete_connection`: calls `annotations::delete_annotations_for_connection` before `appdb::delete_connection`. Do not remove this call.

### Keyring helpers (`lib.rs`)
- `keyring_entry(account) -> Result<Entry, String>` — builds a keyring entry for `service="intelquery", account=<account>`
- `credential_set(account, secret)` — store a secret in OS keychain
- `credential_get(account)` — retrieve a secret; returns `None` if absent
- `credential_delete(account)` — remove a secret

**Account naming conventions:**
- Connection passwords: `conn_{connection_id}_password`
- OpenRouter API key: `openrouter_api_key`
- R2 secret access key: `r2_secret_access_key`

### `sync.ts` (frontend)
- All functions call `safeInvoke<T>()` from `utils/tauri.ts`
- `sync.getSetting(key)` / `setSetting(key, value)` — used across many modules for persistence
- `sync.listConnections()` / `saveConnection()` / `deleteConnection()` — used by ConnectionsManager
- `sync.getSettings()` — used at startup to hydrate AiSettingsContext and R2 settings

## SQLite Schema

```sql
CREATE TABLE connections (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  db_type TEXT NOT NULL,
  host TEXT NOT NULL DEFAULT '',
  port INTEGER NOT NULL DEFAULT 0,
  database TEXT NOT NULL DEFAULT '',
  username TEXT NOT NULL DEFAULT '',
  sort_order INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at TEXT NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE settings (
  key TEXT PRIMARY KEY,
  value TEXT
);

-- annotations table — created by annotations::init_schema (MOD-002)
-- see src/components/annotations/CONTEXT.md for schema
```

## Critical Constraints

- **Rollback-journal mode is intentional**: WAL would create sidecar files (`-wal`, `-shm`), breaking the single-file R2 backup assumption. Do not change `journal_mode`.
- **No passwords in this DB**: always use `credential_set` / `credential_get` for secrets.
- **`init_schema` is pub**: must remain `pub` so `annotations::init_schema` can be called from it, and so `lib.rs` can call it after restore.

## Related Modules

- All other modules depend on this for persistence
- **MOD-005** backs up this file to R2 — any schema change must remain backward-compatible with restored backups
- **MOD-002** adds the `annotations` table via `init_schema` (called from this module)

## Contract

- `sync.getSetting(key)` / `setSetting(key, value)` / `deleteConnection()` / `listConnections()` — used by every other module for persistence. @anchor src/services/sync.ts
- `credential_set(account, secret)` / `credential_get(account)` / `credential_delete(account)` — the only safe way to store secrets. @anchor src-tauri/src/lib.rs
- `init_schema` is `pub` — called from `lib.rs` after a backup restore to re-initialize tables. @anchor src-tauri/src/appdb.rs

## Invariants

- `journal_mode` must stay `Delete` (rollback-journal, not WAL) — MOD-005 reads the raw `.db` file and requires a single-file snapshot. @anchor src-tauri/src/appdb.rs
- Never store passwords or API keys in the SQLite DB — always use `credential_set`. Account naming: `conn_{id}_password`, `openrouter_api_key`, `r2_secret_access_key`. @anchor src-tauri/src/lib.rs
- `appdb_delete_connection` calls `annotations::delete_annotations_for_connection` before `delete_connection` — do not remove this cascade. @anchor src-tauri/src/lib.rs

## Internal

- Settings table is generic key-value (`key TEXT PRIMARY KEY, value TEXT`) — any module may store settings here. @anchor src-tauri/src/appdb.rs
- `port` is `i64` in `ConnectionRecord` — matches SQLite INTEGER storage. @anchor src-tauri/src/appdb.rs
- Adding a new table: create a migration inside `init_schema`, not as a separate DDL call. @anchor src-tauri/src/appdb.rs
