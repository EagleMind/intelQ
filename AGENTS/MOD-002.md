## Key Facts (quick reference)

- **Two modes**: `virtual` (local SQLite only) and `native` (writes COMMENT to target DB)
- **ID format**: `"{connection_id}:{table_name}:{column_name ?? ''}:{scope}"` — deterministic, enables upserts
- **Auto-load**: `AnnotationContext` listens to `DbContext.status.connectionId` and loads automatically on connect
- **Native support**: PostgreSQL (table + column), MySQL (table only), SQLite (disabled)
- **Panel state** is self-managed inside `AnnotationContext` (`isPanelOpen`, `panelTable`, `openPanel()`, `closePanel()`)
- **Cascade delete**: deleting a connection in `appdb_delete_connection` calls `annotations::delete_annotations_for_connection` first
- **Export formats**: JSON (re-importable), SQL (COMMENT statements), Markdown (docs), CSV (flat)

## Tauri Commands Owned

| Command | Purpose |
|---------|---------|
| `annotation_save` | Upsert annotation in local store (+ native COMMENT if mode=native) |
| `annotation_get_all` | Fetch all annotations for a connection |
| `annotation_delete` | Remove one annotation by ID |
| `annotation_export` | Serialize to JSON/SQL/Markdown/CSV |
| `annotation_apply_native` | Execute COMMENT SQL on the connected DB |
| `annotation_fetch_native` | Read COMMENTs from pg_description / information_schema |

## Security Constraints

- `validate_table_name()` must be called before using table/column names in raw SQL (already done in `annotation_apply_native`)
- No secrets stored; the annotation body text is plain user content
